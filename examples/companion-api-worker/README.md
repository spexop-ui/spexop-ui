# Bounded local API worker caller (synthetic Input)

This is a trusted, local caller for [issue #18](https://github.com/spexop-ui/spexop-ui/issues/18). It wires the Groq adapter into the existing companion coordinator for one reviewed public synthetic Input task. It is not a desktop app, a general project runner or product acceptance.

The caller accepts only the eight-file fixture inventory and the public baseline `src/Input.tsx` hash. The worker may replace only that Input file. It cannot choose a provider, model, endpoint, extra source or paid fallback. The main agent remains responsible for the task contract, approval, dependency review and independent Chrome observation.

## Three explicit steps

1. Prepare a private copy of the [synthetic fixture](../../docs/benchmarks/groq-input-2026-11-01/fixture/) with `src/Input.tsx` replaced by the [public baseline](../../docs/benchmarks/groq-input-2026-11-01/evidence/baseline-Input.tsx). Review its eight source files and install its pinned dependencies in that isolated copy. Build a contract with the coordinator's `snapshot`/`createState`; bind its exact contract hash, source hash, model, limits and sharing decisions in a private mode-0600 approval JSON. The owner must authorize each new provider transaction separately. A prior two-attempt approval cannot be reused.
2. After `pnpm build` in this repository, run `node examples/companion-api-worker/run.mjs preflight <contract.json> <approval.json>`. It validates source and approval binding and prints only sanitized metadata. It never reads a key or calls Groq. `execute` additionally requires an owner-approved private key file, reviewed `node_modules`, a new private output directory, `accessVerified: true`, `costApproved: true`, and an `observedAt` value in the approval. No default executable command or credential discovery is provided.
3. `execute` reserves the approval file once before transport, calls the bounded worker, creates isolated candidates and runs fixed TypeScript, ESLint and Vite checks. Browser evidence stays `UNKNOWN`. After a real Chrome review of the current candidate, write a private JSON receipt in the output directory containing `{ "revision": "<candidate revision>", "result": "PASS|FAIL|UNKNOWN", "reason": "<observed behavior>" }`. Run `node examples/companion-api-worker/run.mjs record-browser <output-dir> <receipt.json>`. It refuses stale source/candidate revisions. A browser receipt reflects a trusted reviewer observation; the local checksum does not authenticate the reviewer.

The caller persists a private journal and sanitized check files. It never executes model-supplied commands or writes model output into the source project. A failed deterministic check may use a second attempt **only if** the exact contract and approval allow it, including feedback sharing. The `.used` reservation blocks accidental reuse of the same approval file across new output directories; it is a local replay guard, not authenticated owner consent. Interrupted runs are not automatically resumed. The operator must inspect the journal and provider account usage before deciding on a new task.

The [1 November live probe](../../docs/benchmarks/r1-input-live-2026-11-01/README.md) predates this caller and failed its independent checks. This path is prepared for a future separately authorized local task; it has not established G-VERIFY, external acceptance, desktop packaging or release readiness.
