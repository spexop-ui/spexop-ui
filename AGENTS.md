# Agent starting point

Spexop UI is a free, local-first, open-source UI/UX desktop companion **in development**. Public source is available under MIT; there is no installable desktop release or accepted product API worker yet.

Before proposing or changing work:

1. Read [README.md](README.md) for current source and product status, [docs/roadmap.md](docs/roadmap.md) for stages and acceptance gates, and [CONTRIBUTING.md](CONTRIBUTING.md) for contribution rules.
2. Check the live [M5 milestone](https://github.com/spexop-ui/spexop-ui/milestone/1) and its open issues for current scoped work. As of 1 November 2026, [issue #18](https://github.com/spexop-ui/spexop-ui/issues/18) is the next bounded product-worker task; verify its live state before relying on that date.
3. Maintainers use [Project #5](https://github.com/orgs/spexop-ui/projects/5) for execution status. It is private. If you cannot access it, use the public roadmap, milestone and issues; do not infer that no work exists. The Engineering Master is the canonical management record for authorized maintainers.

The roadmap describes direction, the milestone groups repository issues and PRs, and each issue defines a bounded task. An item can appear in both the milestone and Project. Historical notes and closed work remain evidence, not current status.

Keep claims separate: PR #13 is an internal test-double prototype; PR #17 is a separate synthetic Groq benchmark with partial acceptance. G-VERIFY, G-EXTERNAL-ACCEPT, packaged desktop, product worker integration and release approval remain open. Do not claim an npm or product release from tests or public source availability.

Use only the task's authorized scope. Do not put credentials, private project content, customer data or unlicensed assets into public issues, PRs or source. Do not activate GitHub Actions or Copilot review, make provider transactions, publish packages or change release visibility without a separate owner decision.
